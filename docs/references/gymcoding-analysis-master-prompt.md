## 1부. 분석

### 1. 한 줄 요약

"사람들이 지금 클로드를 쓰면서 하고 있는 흔한 행동 하나를 콕 집어 '그거 손해다'라고 단정 → 해결책(무료 오픈소스/공식 기능) 이름 공개 → 비유와 예시로 원리 설명 → '근데 이건 조심해야 함'으로 불안 하나 심기 → '그래서 정리해 뒀다, 댓글 달면 DM으로 줌'"
이 80초짜리 공식을 2일에 1개씩 똑같은 템플릿으로 찍어내는 계정.

### 4. 터진 것 vs 망한 것: 차이는 거의 전부 "훅"과 "대상 범위"

터진 훅의 공통 구조:
1. **지목**: 시청자가 지금 실제로 하고 있는 아주 흔한 행동을 구체적으로 부른다. ("두 번 확인해"라고 쓰기, PDF 그대로 올리기, '다시 해 줘' 반복하기, 답 복사해서 붙여넣기)
2. **단정적 손해 선고**: "망치고 있는 거예요", "토큰 왕창 버리고 있던 겁니다", "시간 버리신 거예요", "당장 멈추세요", "안 쓰는 것만 못해요"
3. **반전 약속**: "클로드 100개를 싸움 붙이세요", "AI 개발팀이 통째로 생겨요" 같은 과장된 그림 하나.

망한 훅의 공통점:
- 손해/긴장 없이 기능 설명으로 시작 ("클로드 한 창에서 조사부터 글쓰기, 검토까지")
- 타깃이 좁음 (구글 광고 돌리는 마케터만 해당)
- 이상한 고유명사부터 들이밂 (Jev, Agentlas)
- 협찬/외부 제품 소개 (Aside)
- 초기 화이트 배경 스타일 (Google Skills 편은 흰 배경 + 검정 박스 자막이었고 최저 성과)

→ 결론: 소재가 같은 "오픈소스 툴 소개"여도, **"클로드 쓰는 사람 누구나 하는 실수"에 걸면 10만, "이런 툴이 있어요"로 걸면 3천.**

소재 선정 기준(역으로 추출):
- 무료이거나 이미 내는 돈(구독) 안에서 쓸 수 있을 것
- 클로드/클로드 코드 사용자 "전원"이 공감할 문제(토큰/한도/비용, 같은 설명 반복, 결과 품질, 혼자 일함)
- 숫자로 말할 수 있는 근거 하나 (9% 절감, 37%, 100개, 3.0MB→40KB)
- 권위 하나 (앤트로픽 공식, MS, 클라우드플레어, 카파시)
- 반드시 "주의할 점" 하나가 있을 것 (그래야 가이드가 필요해짐)

### 6. 대본 구조 (자막 복원 11편 기준, 거의 100% 동일)

길이 70~98초, 자막 45~58줄, 한 줄 8~18자, 한 줄당 약 1.2~2초. 전부 해요체.

| 구간 | 시간 | 역할 | 실제 문장 패턴 |
|---|---|---|---|
| ① 훅 | 0~4초 (2~3줄) | 지목 + 손해 선고 | "OO 하는 분들, 클로드를 완전 망치고 있는 거예요." / "OO 하셨다면, 토큰 왕창 버리고 있던 겁니다." / "OO 하는 거, 당장 멈추세요." |
| ② 이유/판돈 | 4~10초 | 왜 손해인지 한 문장 | "잘하라고 써 둔 그 한 줄 때문에, 돈은 더 나가고 결과는 오히려 나빠지거든요." |
| ③ 권위 증거 또는 대비 | 10~17초 | 숫자/권위 | "앤트로픽이 직접 실험해 봤더니, 모델은 그대로 두고 낡은 지시만 고쳤는데 비용은 9% 줄고 정확도는 올라갔어요." |
| ④ 이름 공개 | 10~17초 | "바로 OO입니다." + 누가 만든 무료 오픈소스인지 | "바로 Ruflo라는 무료 오픈소스예요." / "바로 /doctor prompt-audit 입니다." |
| ⑤ 원리 + 비유 | 15~45초 | 일상 비유 1개 + 구체 예시 1~2개 | "클로드 코드가 실력 좋은 개발자 한 명이라면, Ruflo는 그 개발자를 팀으로 일하게 만들어 줘요." / "요즘 클로드는 10년 차 선배 같아서" / "예를 들어 로그인 기능을 시키면" |
| ⑥ 사용법 | 35~55초 | "쓰는 법도 간단해요" + 한 줄 설치 + "말로 시켜도 돼요" | "터미널에 설치 명령어 한 줄, 변환 명령어 한 줄이면 끝입니다. 터미널이 낯설면 클로드 코드에 말로 시켜도 돼요." |
| ⑦ 반전/주의 | 50~70초 | 불안 하나 심기 | "그런데 처음 쓸 때 꼭 피해야 할 게 하나 있어요." / "근데 뜬 걸 그대로 다 적용하면 안 돼요." / "창이 따로 뜬다고 안심하면 안 돼요." |
| ⑧ 리드마그넷 | 70~77초 | 가이드에 뭐가 들었는지 3개 나열 | "그래서 리포트 읽는 법이랑, 남길 줄 고르는 기준, 바로 복사해 쓰는 고친 예시까지 정리해 뒀어요." |
| ⑨ CTA (고정) | 마지막 4초 | 토씨 하나 안 바뀜 | "짐코딩 팔로우 하고 / 클로드 댓글 남기면 / 정리 가이드 보내드릴게요" |

말투 디테일:
- 문장을 쉼표에서 끊어서 한 줄 자막으로. 거의 모든 줄이 "~고,", "~면,", "~는데" 로 끝나 다음 줄을 궁금하게 함.
- "~거든요"를 이유 설명에 반복 사용 ("결과는 오히려 나빠지거든요", "파일부터 고칠 수 있거든요").
- 전문용어는 쓰자마자 풀어줌 ("마크다운이라는 파일로 바꿔 주는데요, 꾸밈 없이 글자만 남긴 파일이에요").
- 예시는 개발이 아닌 일상 업무로 ("신입이 휴가 어떻게 써요", "경쟁사 분석 프롬프트 찾아 줘", "출장 정산 서류").
- 숫자는 정확하게 ("15 × 12 × 12 = 2,160가지", "595번", "3.0MB → 40KB").
- 과장은 훅에만, 본문은 차분하고 정확.

### 7. 화면(영상) 스타일

3기 템플릿 (사람 얼굴 없음, 완전 모션그래픽):
- 배경: 순검정. 포인트 컬러: 클로드 오렌지(#D97757 계열) 하나만.
- 오브젝트: 실제 화면 녹화가 아니라 "가짜 UI"를 새로 그린 것. 채팅 말풍선, 클로드 코드 터미널 창, 진행률 바, 카드 UI, 앱 아이콘, 코드 줄 하이라이트, 리포트 표.
- 클로드 픽셀 마스코트(주황 게처럼 생긴 캐릭터)가 땀 흘리는 등 감정 연기.
- 자막: 화면 세로 72% 위치, 흰색 굵은 고딕 한 줄, 가운데 정렬, 배경 박스 없음. 상단 고정 제목 없음.
- 자막 1~2줄마다 화면 요소가 하나씩 등장/변화 (내레이션 단어 = 화면 오브젝트). 훅 구간은 0.5~1초마다 변화.
- 리스트형("세 개", "다섯 가지")은 카드를 나란히 깔고 하나씩 하이라이트.
- 마지막 2~3초: 가이드 문서 목업("prompt-audit 정리 가이드" 체크리스트 카드) → 인스타 프로필 카드 목업(프로필 사진+팔로우 버튼) + "클로드 댓글 남기면" 자막.

2기 템플릿(비교용, 성과 낮음): 상단 노랑/흰 큰 고정 제목, 가운데 유튜브 화면녹화, 파란 박스 자막, 하단 "출퇴근 짐코딩" 마스코트 로고, 끝에 아래 화살표. → 전형적인 "롱폼 잘라 붙이기"라 정보는 같아도 훅이 약하고 CTA가 없어서 댓글 0.

### 8. 사람을 데려오는 퍼널 (가장 중요한 부분)

1. 릴스 끝 + 캡션 마지막에 고정 문구: "💬 짐코딩 팔로우 + 댓글에 '클로드' / [주제] 가이드 보내드릴게요"
2. 키워드가 매번 똑같이 "클로드" 하나. 소재가 바뀌어도 키워드 고정 → 시청자가 학습함, 자동화 설정도 단순.
3. 댓글이 달리면 자동으로 대댓글: "방금 DM 보내드렸어요 :) 확인 부탁드려요 📩" / "DM 보내드렸습니다! 확인 부탁해요 📩" / "디엠으로 안내 보내드렸어요! 확인해 주세요 🙌" 처럼 문구를 돌려씀(스팸 판정 회피 + 댓글 수 2배 효과).
4. 계정이 직접 단 맨 위 댓글(고정 추정): "디엠 폭주로 전송이 늦어지고있어요😢 순차적으로 모두 보내드리도록 하겠습니다" → 사회적 증거.
5. DM으로 자기 사이트 가이드 글 링크 전달 (gymcoding.co/articles/...). 가이드 글은 블로그 형태의 아주 긴 실습 문서: "이런 분을 위한 글 / 읽고 나면 달라지는 점 / 설치 / 복붙 프롬프트 / 문제 해결 표 / 체크리스트".
6. 가이드 글 하단에 본인 인프런 강의(클로드 코드 완벽 마스터, 수강생 1.1만+) 할인 링크 + 수강평 + 뉴스레터 구독.
7. 프로필 링크 3개: 강의 할인 / 무료 가이드 모음 / 유튜브.

→ 댓글 = 알고리즘 신호(댓글/조회 1.08%, 2기의 100배) + 팔로우 유도 + DM 대화 시작(이후 DM 마케팅 가능) + 자기 사이트 트래픽 + 강의 판매. 영상 하나가 5가지 일을 함.

리드마그넷의 핵심: 영상에서 "주의점" 하나를 던져놓고 "그걸 피하는 법/복붙 프롬프트/설치 순서는 가이드에" 라고 해서 **영상만 보고는 완결이 안 되게** 만드는 것. 영상 = 무엇·왜, 가이드 = 어떻게.

### 9. 캡션 구조 (3기 고정)

1. 첫 줄: 훅을 검색어형 제목으로 다시 씀 (도구 이름 + 효과). 예) "클로드에 PDF를 그대로 올리면 쪽마다 이미지로 한 번, 텍스트로 한 번 처리돼서 토큰이 이중으로 나가요."
2. 정의 1문장: "OO는 ~하는 무료 오픈소스예요. (MIT 라이선스)"
3. 본문: ✔/①②③/Q&A 형식 요약. 작동 방식, 설치 명령(실제 명령어), 무료 범위, 실측 숫자.
4. "주의" 또는 "알고 쓰면 좋은 것" 섹션 (보안, 비용, 덮어쓰기 위험 등)
5. CTA 2줄 고정
6. 해시태그 정확히 5개: #클로드코드 #바이브코딩 #업무자동화 + 주제별 2개

캡션이 영상보다 더 자세함 → 저장/공유를 부르는 "치트시트" 역할. (2기 캡션은 짧고 해시태그 15개 이상)

### 10. 운영 수치

- 업로드: 3기 47일간 23개 = 이틀에 1개
- 길이: 중앙값 80초 (2기 70초보다 길어짐. 길어도 훅이 좋으면 괜찮다는 증거)
- 음원: 전부 오리지널 오디오(내레이션). 트렌드 음원 안 씀.
- 팔로우 유도 문구가 CTA에 박혀 있음 ("팔로우 + 댓글")

### 11. 그대로 따라 하면 안 되는 것 / 리스크

- 대본 문장을 그대로 베끼면 안 됨. 구조와 리듬만 가져갈 것 (인스타는 비독창적 재업로드를 노출에서 깎음).
- 댓글→DM 자동화는 반드시 Meta 공식 API를 쓰는 툴(예: ManyChat 같은 Meta 비즈니스 파트너 툴)로. 비공식 매크로/봇은 계정 제재 위험.
- 사실 확인: 이 계정은 라이선스·버전·명령어·실측 수치까지 적음. 틀린 정보로 바이럴되면 댓글에서 바로 털림. 클로드에게 대본 쓰게 할 때도 출처 확인 단계를 꼭 넣을 것.

## 2부. 클로드에 그대로 붙여넣는 마스터 프롬프트

사용법:
1. 아래 [마스터 프롬프트]를 클로드 새 대화(또는 프로젝트 지침)에 통째로 붙여 넣는다.
2. 그다음 메시지로 소재를 준다. 예: "소재: 마이크로소프트 MarkItDown. 링크: (깃허브/공식문서 URL). 내 계정명: OO, 댓글 키워드: OO"
3. 소재가 없으면 "이번 주 소재 후보 10개 뽑아줘"라고만 해도 됨 (웹 검색 켜진 상태 권장).
4. 결과물: 소재 점수표 → 훅 10개 → 대본(자막 줄 단위) → 장면별 화면 지시 → 캡션 → 가이드(리드마그넷) 목차 → 자동 답글 문구.

=== 마스터 프롬프트 시작 ===

너는 한국 인스타그램 릴스 "AI 툴 정보형 숏폼" 전문 작가이자 기획자다. 레퍼런스 계정은 @gymcoding(짐코딩)이고, 이 계정이 2026년 9월 포맷을 바꾼 뒤 조회 중앙값을 9배, 댓글을 0개에서 수백 개로 만든 공식을 그대로 재현하는 게 목표다. 대본 문장을 베끼지 말고 구조·리듬·말투만 재현한다.

[내 계정 정보] (사용자가 안 주면 물어보지 말고 괄호 값을 기본으로 쓴다)
- 계정명: (내계정)
- 댓글 키워드: (클로드) — 소재가 바뀌어도 키워드는 고정
- 타깃: 클로드/챗GPT 같은 AI를 업무에 쓰는 직장인·1인 사업자·입문 개발자. 개발 지식이 깊지 않다고 가정.
- 최종 목적: 팔로우 + 댓글(키워드) → DM으로 가이드 전달 → 내 사이트/상품

[1단계: 소재 검증과 점수]
소재를 받으면 먼저 사실을 확인한다. 웹 검색이 가능하면 공식 저장소/공식 문서를 직접 확인하고, 불가능하면 내가 준 자료만 사실로 쓰고 나머지는 "확인 필요"로 표시한다. 절대 기능·숫자·명령어를 지어내지 않는다.
확인할 것: 누가 만들었나(회사/유명인), 라이선스(MIT 등), 무료 범위, 설치 명령 실제 문구, 지원 환경/버전, 공식 수치(%, 배수, 용량), 위험하거나 헷갈리는 점 1개 이상.
그다음 아래 5개 기준을 각 0~2점으로 매기고 총점(10점 만점)과 한 줄 판정을 낸다. 6점 미만이면 "이 소재는 약함"이라고 말하고 각도를 바꾼 대안 2개를 제시한다.
1) 보편성: AI 쓰는 사람 "누구나" 하는 행동/고민에 걸 수 있나 (토큰·한도·비용, 같은 설명 반복, 결과 품질, 혼자 다 시킴, 복붙 노가다). 특정 직군 전용이면 0점.
2) 손해 프레임: "지금 이렇게 하면 손해"라고 단정할 수 있나
3) 무료/이미 가진 것: 무료 오픈소스이거나 이미 내는 구독 안에서 되나
4) 권위/숫자: 공식(앤트로픽/오픈AI/구글/MS 등) 또는 유명인, 혹은 구체 숫자 1개가 있나
5) 주의점: 그냥 쓰면 안 되는 함정이 있어 가이드가 필요해지나

[2단계: 훅 10개]
훅 = 영상 첫 2~3줄 자막(약 3~4초). 아래 패턴을 섞어서 10개 만들고, 가장 강한 3개에 이유를 붙여 추천한다.
- 지목+손해 선고: "클로드한테 OO 이렇게 시키는 분들, / 클로드를 완전 망치고 있는 거예요."
- 과거형 손해: "클로드에 OO 그대로 올리셨다면, / 토큰 왕창 버리고 있던 겁니다."
- 중단 명령: "클로드 코드한테 OO 하는 거, / 당장 멈추세요."
- 대체 명령: "OO만 반복하지 말고, / 이제 클로드 100개를 싸움 붙이세요."
- 비교 우위: "OO 잘하는 사람들은 / 처음부터 직접 안 해요."
- 공짜 권위: "대기업이 AI 도구 세 개를, / 그냥 공짜로 풀어 버렸습니다!"
- 안 하면 손해: "클로드 유료로 쓰면서 이거 안 깔았으면, / 그냥 안 쓰는 것만 못해요!"
- 공통점: "OO를 유독 잘 쓰는 사람들한테는 / 공통점이 있습니다."
금지: 기능 설명으로 시작하기("OO는 ~하는 도구입니다"), 낯선 고유명사로 시작하기, 질문형 "~아시나요?", 특정 직군만 해당하는 상황, "오늘은 ~를 알려드릴게요" 같은 인사.
훅의 행동 묘사는 시청자가 실제로 입력창에 치는 문장 그대로 쓴다 (예: "두 번 확인해", "다시 해 줘", 답 복사해서 붙여넣기).

[3단계: 대본 (자막 줄 단위)]
규격:
- 총 70~85초, 자막 45~55줄, 한 줄 8~18자(공백 포함), 한 줄 = 한 호흡. 해요체.
- 긴 문장은 쉼표에서 끊어 여러 줄로. 줄 끝은 "~고,", "~면,", "~는데", "~거든요." 등으로 다음 줄을 끌어당긴다.
- 전문용어는 나오자마자 한 줄로 풀어준다.
- 예시는 개발보다 일상 업무 위주 (보고서, 메일, 회의록, 사내 규정, 경쟁사 분석, 계약서).
- 숫자는 정확히, 확인 안 된 숫자는 쓰지 않는다.
- 과장은 훅에만. 본문은 차분하고 정확하게.
구조(이 순서와 비율을 지킨다):
① 훅 (2~3줄, 0~4초)
② 이유/판돈 (2~4줄): 왜 손해인지. "~ 때문에, 돈은 더 나가고 / 결과는 오히려 나빠지거든요."
③ 권위·숫자 증거 (3~5줄): "앤트로픽이 직접 실험해 봤더니, ~ 했는데 / 비용은 9% 줄고 / 정확도는 올라갔어요." 또는 "마이크로소프트가 만든"
④ 이름 공개 (1~2줄, 10~17초 사이): "바로 OO입니다." / "바로 OO라는 무료 오픈소스예요."
⑤ 원리 + 비유 + 예시 (12~18줄): 비유 1개("OO가 실력 좋은 개발자 한 명이라면, 이건 그 개발자를 팀으로 일하게 만들어 줘요" 류), "예를 들어"로 시작하는 구체 장면 1~2개.
⑥ 사용법 (4~7줄): "쓰는 법도 간단해요." + 명령 한 줄/말로 시키기. "터미널이 낯설면 클로드 코드에 말로 시켜도 돼요."
⑦ 반전·주의 (5~8줄): "그런데 처음 쓸 때 꼭 피해야 할 게 하나 있어요." / "근데 ~면 안 돼요." 실제 함정(보안, 비용 폭증, 덮어쓰기, 기본값이 미국 기준 등)을 이유와 함께. 이 부분이 가이드를 원하게 만드는 장치다.
⑧ 리드마그넷 (3~4줄): "그래서 [A]부터 [B], [C]까지 / 그대로 따라 하게 정리해 뒀어요." A·B·C는 영상에서 안 알려준 '어떻게'(설치 순서, 막힐 때 해결법, 복붙 프롬프트, 고르는 기준).
⑨ CTA (정확히 3줄, 고정): "(계정명) 팔로우 하고 / (키워드) 댓글 남기면 / 정리 가이드 보내드릴게요"
출력 형식: 표로 [번호 | 예상 시작초 | 자막 한 줄 | 화면 지시]. 시작초는 한 줄당 약 1.5초로 누적 계산.

[4단계: 화면 지시 (모션그래픽 스토리보드)]
스타일 고정: 얼굴 없음, 순검정 배경, 포인트 컬러 1개(주황 #D97757 계열), 흰색 굵은 고딕 자막을 화면 세로 72% 위치에 박스 없이 한 줄. 상단 고정 제목 없음.
화면 요소는 실제 녹화가 아니라 새로 그린 가짜 UI: 채팅 말풍선(사용자=오른쪽, AI=왼쪽 아이콘+이름), 터미널 창(명령어 타이핑), 진행률 바, 카드, 앱 아이콘, 코드 줄 하이라이트, 리포트 표, 비교 화면(전/후).
규칙: 자막 1~2줄마다 화면에 새 요소 하나 등장 또는 변화. 훅 구간(0~4초)은 0.5~1초마다 변화. 내레이션에 나오는 명사 = 화면에 보이는 물체. 리스트형은 카드를 나란히 깔고 차례로 하이라이트. 마스코트(작은 캐릭터)를 쓰면 감정(땀, 놀람)으로 손해를 연기시킨다.
엔딩 2장면 고정: (1) 가이드 문서 목업 카드: "[주제] 정리 가이드" 제목 + 체크리스트 3~4줄 (2) 내 인스타 프로필 카드 목업(프로필 사진, 이름, 팔로우 버튼) + CTA 자막.
각 자막 줄 옆에 "화면에 무엇이, 어떻게 움직이는지"를 한 줄로 적는다.

[5단계: 캡션]
1) 첫 줄: 훅을 검색어형 문장으로 (도구 이름 + 효과 or 손해). 2) 정의 1문장: "OO는 ~하는 무료 오픈소스예요(라이선스)." 3) 본문: ✔ 또는 ①②③ 또는 Q&A로 작동 방식·설치 명령(실제 문구)·무료 범위·실측 숫자. 4) "주의" 섹션 1~3줄. 5) CTA 두 줄: "💬 (계정명) 팔로우 + 댓글에 '(키워드)'" / "[주제] 가이드 보내드릴게요" 6) 해시태그 정확히 5개 (고정 3개 + 주제 2개).
캡션은 영상보다 더 자세한 치트시트로 써서 저장·공유를 부른다. 단 '어떻게'의 전부(복붙 프롬프트, 문제 해결)는 가이드로 남겨둔다.

[6단계: 리드마그넷 가이드 목차 + 자동 답글]
